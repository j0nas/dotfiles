Pace agent work to the account's quota with `claude-quota` (`--help` for the rest). The quota is a budget for the work at hand, not a pace to keep: the weekly target is 92% used at the reset (the user's number; the rest is theirs), and the 5-hour window is the short-term limit, planned to 90% at most.

- **When**: before fanning out agents, between batches on a long unattended run, and when the user asks. Log each agent: `claude-quota start "<label>" <model> --kind <implement|review|research|design|mechanical>` when you launch it, `claude-quota end <id> <tokens> --outcome <merged|fixed|partial|discarded>` from its notification. That log is what `learn` fits; an unlogged agent teaches nothing.
- **Plan from the backlog**: `claude-quota plan sonnet:implement=3 opus:design=1` prices what is still to do against both windows, counting what the agents already running will still spend. It fits: run it as wide as the 5-hour window allows. Short on the week: move agents down a model (workflow-model-cost has the tiering) before dropping work. Short on the 5-hour window: start what fits and queue the rest with `claude-quota queue add "<label>" <model>:<kind> --note "…"`.
- **Suspend before the 5-hour limit, resume after it**: the limit stops every running agent mid-task, and nothing restarts them. So whenever agents run, keep `claude-quota watch` going as a background command; it exits (waking the session) when the window will hit its limit before it resets. Then tell each agent to commit its work in progress and stop, saying where it was; log each with `claude-quota suspend <id> --ref <agent id> --note "…"`; queue what hasn't started; and run `claude-quota wait` as a background command. It exits at the reset with the list to resume (SendMessage each suspended agent) and start (price it with `plan` first). If agents were stopped by the limit before you could act, log them with `suspend` the same way and start `wait`.
- **Never pad**: when the backlog is done, stop and ask the user for more instead of inventing work to use the budget. Near the weekly reset with a large spare, spend it on quality: a stronger model where judgement matters, a review pass on what shipped.
- **The situation**: user away → go wide. User at the keyboard → leave room in the 5-hour window for their own use. Delegate file-heavy work to agents and compact at natural breaks: every turn of the main session re-reads its whole context, a cost the tool can't see.
- **Limit resets**: log one from Settings > Usage with `claude-quota reset add <week|5h|both> <expiry> --note "…"`; `status` and `plan` then count it as a full week more until it lapses. With one open, run the week toward its limit before the expiry and remind the user to redeem it (web or desktop app only). The tool notices the redemption itself.
- **Learn**: run `claude-quota learn` now and then; its outcomes per model and kind say which tasks a cheaper model handles well. Tell the user when a plan changes because of the quota, in one line.
