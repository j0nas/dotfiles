# Measurement commands

`codebase-baseline` is one Go binary (source: `tools/cmd/codebase-baseline`, built into `~/.local/bin` by chezmoi). It measures without an LLM, so a later run is comparable. Everything except `run-loops` is static: it never executes the analysed repo's code and never writes inside it. Every git call goes through one wrapper that disables fsmonitor, hooks and optional locks, so a hostile `.git/config` runs nothing (the external secret scanner, if installed, runs git itself). Every JSON file carries `schema_version` and `tool` (version and VCS revision); `diff` warns when two snapshots come from different tool versions, line counters or secret scanners. A metric that cannot be measured is recorded as `"unavailable": "<reason>"`, never as 0. Flags may come before or after the positional arguments.

## Subcommands

| Command | What it does | Writes |
|---|---|---|
| `export <repo> <dest> [--strip-docs] [--keep <glob>]...` | Copies HEAD's tracked files into `dest` by reading git objects: the repo's index is untouched, `export-ignore` does not drop tests or CI, no filter or hook runs. A folder inside a bigger checkout exports only that subtree and says so. Always left out: symlinks, submodules and secret-like files (tracked `.env*` except `.example/.sample/.template/.dist`, `*.pem *.key *.p12 *.pfx *.keystore`, `id_rsa*`, `credentials*.json`). `--strip-docs` also deletes prose docs (.md .mdx .rst .adoc, README/CHANGELOG-style notes, `docs`/`adr`/`decisions`/`wiki`/`rfcs` directories at any depth, case-insensitive) and agent files (AGENTS.md, CLAUDE.md, `.claude/`, `.cursor/`, `.aider*` and the like); `--keep` retains doc files that are content or code (`--keep 'site/content/**' --keep 'prompts/*.md'`). Refuses a non-empty `dest`. | `dest/`, `dest.removed.txt` (path, reason) |
| `discover <repo> --out loops.json` | Finds candidate loops (install, typecheck, lint, test, build, e2e, format, audit) for JS/TS, Python, Go, Rust, Gradle/Maven, .NET, Ruby, PHP, make/just/task, and the `run:` steps of GitHub Actions and GitLab CI. Runs nothing. npm `pre`/`post` hooks and one level of nested `npm run`/`pnpm run`/`yarn` calls are resolved before the `needs` analysis. A loop whose text calls a deploy or publish tool (vercel, terraform, kubectl, aws, docker push, npm publish, prisma migrate deploy ...) is disabled with `needs: ["deploy-tool:<name>"]`. Tracked config files (application*.yml, appsettings*.json, settings*.py, config/*, docker-compose*, .env.example) that point at non-local hosts disable that project's test/e2e/integration loops with `needs: ["external-config:<file>"]` (hosts are listed in `signals.external_config`, credentials never). Up to 40 projects per ecosystem; every cut is listed in the top-level `truncated`. Audit loops (`pnpm/npm/yarn audit --json`, `pip-audit`, `govulncheck ./...`, `cargo audit`, `bundle audit`) are on for the JS managers and, for the rest, only when the tool is on PATH (else `needs: ["tool:<name>"]`). | `loops.json` |
| `run-loops <loops.json> --workdir <export> --out results.json [--repeat-tests 2] [--only id,id] [--total-timeout 45m]` | Runs the enabled loops in order inside the export, from an empty environment: PATH, TMPDIR, USER, SHELL, LANG, CI=1, the loop's `extra_env`, and HOME plus `XDG_CONFIG_HOME/CACHE_HOME/DATA_HOME` pointing at `<workdir>/../.home-<name>` (so `~/.ssh`, `~/.aws`, `~/.npmrc` are unreachable; toolchain locations such as mise, rustup, nvm are passed by path). A loop with `"real_home": true` gets the real HOME (for an approved private-registry install) and is recorded as such. `results.json` is rewritten atomically after each loop, so a killed run keeps what finished (`complete: false` until the end). Each loop has its timeout and the run has `--total-timeout`; on a timeout the process group is killed and processes naming the workdir are killed too, but other daemons may survive. Statuses: `passed`, `failed`, `timeout`, `skipped`, `disabled`, `not_selected`, `tool-missing` (exit 127 or command not found: not a code failure), `findings` (an audit exited non-zero with advisory counts: a result, not a broken loop). Records exit code, duration, redacted tails and parsed counts (jest, vitest, node:test, mocha, pytest, go test, cargo, rspec, phpunit, surefire, gradle, dotnet, tsc, eslint, ruff, mypy, npm/pnpm/yarn audit severities, govulncheck). Test loops run `--repeat-tests` times and are `flaky` when counts differ. With `--only`, the selected entries are merged into an existing `--out`; the rest are kept. A failed install skips its dependants. Refuses a workdir that holds a `.git`. | `results.json` |
| `measure <repo> --out snapshot.json [--files-out files.json] [--loop-results results.json] [--metrics run.json] [--months 24] [--as-of YYYY-MM-DD] [--rev <sha>] [--worktree]` | Snapshot of HEAD (exported to a temp dir; `--worktree` scans the working tree; `--rev` measures that commit instead, with history windows ending at its date unless `--as-of` is given, so an old snapshot can be recomputed with this tool version). Sections: `size` (scc; generated, minified and vendored files left out and counted), `git`, `deps`, `hygiene` (CI, hooks, CODEOWNERS, Docker, IaC, env examples, tracked env/secret-like/symlink names, test files, TODOs, secret scan if gitleaks or trufflehog is installed, `ci_kinds_run`), `docs`, `custom`, `loops`. Top level also has `shallow`, `branch`, `loops_not_run` (count and reasons) and `truncated` (copied from the loop results). `deps` and `hygiene.test_files` say `unavailable` when no manifest or test layout is recognised. Contributor counts and shares exclude bots; the agent share is `agent_trailer_share_lower_bound` (known agent addresses in co-author trailers or authors; display names alone do not count). | `snapshot.json`, `files.json` |
| `history <repo> --months 12 --out backfill.json [--step 1]` | Size, test files, direct dependencies and TODO count at the last first-parent commit of each month. Nothing executed. | `backfill.json` |
| `hotspots --files files.json --repo <repo> --days 180 --out treemap.json [--max-leaves 600] [--include-data]` | Joins scc per-file size with git churn into a `{name, churnLabel, children}` tree (leaves: path, loc, churn, complexity, lang; single-child dirs collapsed; generated, vendored, docs and data files dropped). Above `--max-leaves` the smallest files fold into one `other (N files)` leaf per directory. Also top-20 lists by loc x churn and complexity x churn, and a top-level `churnLabel`. | `treemap.json` |
| `scoreboard --run run.json --snapshots <dir> --out scoreboard.json` | The report's `scoreboard-data` (`{note, rows:[{metric, value, first, better, trend, how, asOf, unit, headline}]}`) from every snapshot in the directory, ordered by `meta.measured_at`. Rows are the `metrics` of run.json, or a built-in set when it has none (per-loop test counts, type errors, lint warnings, build, advisories, flaky loops, code lines, dependencies, test files, TODOs, ownership, agent trailer share, reverts, CI present, CI runs tests). `headline: [names]` rows come first. Missing values are `null`; `trend` skips snapshots that lack the metric. Only metrics with a declared direction (failures, errors, warnings, advisories, flaky loops, and `better` in run.json) get `better: up\|down`; gameable counts are `none`. | `scoreboard.json` |
| `diff <old.json> <new.json> [--format md\|json] [--author <regex>] [--repo <path>]` | Absolute and percent change for every numeric metric, loop status and count changes, new and removed CI or hygiene items, warnings for different tool versions, line counters or secret scanners. Only custom metrics with `better` get better/worse. `--author` is anchored (matches the whole name or email, case-insensitive) and counts commits and churn between the two SHAs, lockfiles excluded. | stdout |
| `scrub <dir> [--report <html>]... [--format text\|json]` | Scans every file under `dir` (not node_modules, .git, .venv, `.home-*`) and the report for secret-looking values: AWS keys, Stripe live keys, GitHub/Slack/Google tokens, private key blocks, JWTs, database URLs with passwords, key/secret/token/password assignments. Prints `file:line: pattern: masked value` and exits 1 when anything matches. Run it before a workspace or report leaves the machine. | stdout |
| `check-report <report.html> [--repo <repo>] [--allow <file>] [--format text\|json] [--strict-each] [--list-harvested]` | Cold-reader checks: identifier-like terms (acronyms, labels such as R3.3b or PE-13, CamelCase) without a definition (`<abbr title>`, `<dfn>`, or a following `<sup class="g">` glossary link) unless on the allowlist (generic tech terms only; add yours with `--allow`); with `--repo`, phase, release and ticket labels and codenames harvested from docs, branches and commit subjects; session-leak phrases; broken `#` links and glossary mismatches; every `<script type="application/json">` block must parse, must not contain `<script`, `javascript:` or `on...=` in string values (they would run when text fields render as HTML) or a literal `</script`, and `summary-data` needs exactly 5 facts, 5 risks and 3 actions. Exit 1 when any fail. | stdout |

## run.json metrics

`metrics` entries: `{name, kind:"count", pattern, globs:[...], exclude:[...], unit, better:"up|down|none", note}` count the lines matching an RE2 pattern in the files tracked at the measured commit (read through git, never the working tree's untracked files); they are embedded under `custom` with their definition, so the same count can be taken on later commits. Globs support `**`, `*`, `?`, `{a,b}`; a glob without `/` matches the base name anywhere. `{name, kind:"snapshot", path:"dotted.path", unit, better}` reads a snapshot field (list entries by `loops.loops[id=js-test].parsed.passed`) and is carried through for `scoreboard`. `headline: ["metric name", ...]` leads the scoreboard.

## Order

First baseline: `export` (a run copy, and a `--strip-docs` copy for scanning agents) -> `discover` -> edit `loops.json` (enable what runs offline, add dummy `extra_env`, say why anything is off) -> `run-loops` (rerun one fixed loop with `--only`) -> `measure` (with `--loop-results`, `--files-out`, `--metrics`) -> `history` -> `hotspots` -> `scoreboard` -> `scrub` the workspace and report, `check-report`.

Re-baseline: `export` a fresh copy -> `run-loops` with the same `loops.json` -> `measure` -> `scoreboard` and `diff old.json new.json`.

## Notes

- `measure`, `history`, `hotspots` and `diff --author` read git only; a repo that is not a checkout gets `git: {"unavailable": ...}`. A folder of a bigger checkout limits history to that folder.
- Vendored paths: `node_modules`, `.venv` and `bower_components` anywhere; `vendor`, `coverage`, `dist` and `build` only at the repo root or a project root (a directory with a manifest).
- `run-loops` output tails are redacted (URL credentials, bearer tokens, key=value secrets, AWS secrets, Stripe, Google and GitHub tokens, JWTs, private keys, the `extra_env` values), but the loop itself runs real code: only in an export.
